## Verdict

The entry skill and guides are a reasonable direction, but the two P1 issues should be fixed before opening this as a ready PR. The trial supports short checklists and targeted feedback as promising approaches; it does not establish that this combined, regex-only Symposium implementation preserves the measured quality or cost.

**[P2] Fix the Git output format and decode filenames**

Location: [stop.sh:19-23](/Users/facundo/code/wye/jrr-refactor-trial/just-right-rust/hooks/stop.sh:19), [added-lines.awk:35-55](/Users/facundo/code/wye/jrr-refactor-trial/just-right-rust/hooks/added-lines.awk:35).

The parser assumes an uncolored `+++ b/...` header and hunks without context. `diff.noprefix`, mnemonic prefixes or forced color can silently suppress findings. Default Git quoting makes a filename such as `src/café.rs` fail the header test; quoted `ls-files` output is also passed literally to `--no-index`. With configured inter-hunk context, context lines consume both old and new counts, but the parser decrements its combined count once and never advances the new line number for context, corrupting positions and potentially subsequent file parsing. Ordinary zero-context hunk counting and the protection against mistaking added `+++` content for a header are otherwise sensible. Explicitly control prefixes, color, external diff/textconv and inter-hunk context, and use a filename-safe enumeration and parser. These configuration and quoting behaviors are documented by [Git](https://git-scm.com/docs/git-config#Documentation/git-config.txt-corequotePath) and its [diff options](https://git-scm.com/docs/git-diff).

**“This ships the measured treatment and its measured gains.”** The measured Stop checker ran 14 Clippy lints plus five regex categories, with a 300-second allowance and a once-per-session marker. This branch substitutes two lexical checks for Clippy, changes test exemptions and report limits, and reports newly seen findings repeatedly. **“The hook enforces the Rust rules.”** It detects a small lexical subset. Static counterexamples to each expression follow; these are inferred from [added-lines.awk:25-32](/Users/facundo/code/wye/jrr-refactor-trial/just-right-rust/hooks/added-lines.awk:25), not executed Rust tests.

| Check | False positive or permitted case | Missed case |
|---|---|---|
| Panic | Invariant `expect`; poisoned-lock `unwrap`; unit tests under `src` | `.expect` followed by a newline before `(`; input indexing and arithmetic |
| Cast | `1u8 as u64`, a safe widening conversion | A cast split across lines or using tabs around `as` |
| Stringly typed | Wire fields and protocol-key parameters | `name:String`, multiline types, identifiers with several underscore-separated prefixes |
| String comparison | Comparisons of free text or parser tokens | Direct `match command { "send" => ... }`; many punctuation-leading literals |
| Default/dropped result | Specified `Option` defaults; `let _ =` on a non-`Result`; documented best effort | Multiline calls, `filter_map(Result::ok)`, other error-swallowing branches |
| Untyped error | `Result<HashMap<u8, String>, MyError>` matches the inner comma and `String>` | Aliases, multiline types, differently qualified spellings |
| Weak assertion | Prose `contains`; exact absence/emptiness checks; production `debug_assert!` | Multiline assertions, conditional assertions, implementation-derived expectations |

Only whole-line `//` comments are excluded. Block comments, raw strings and ordinary literals containing matching text remain candidates. Ownership, most simplicity rules, comments and most test-quality rules have no detector.

## Better alternatives

Ranked by expected gain against cost. The proposed small runs are screening experiments, not sufficient evidence for general equivalence claims.

1. **Ship the entry skill and guides first; make blocking hooks optional.** This removes state, platform and interruption risks at very low implementation cost. In the P7/P8 comparison, `short` scores 12.67 versus 13.00 for `hk-start-stop` on greenfield, at 1.27x versus 1.68x control cost. Refactor results favor the hook on average, and P11 suggests feature changes may lose a useful correction step without it, so skill-only is not established as equally effective everywhere ([STATE, P7/P8 table](/Users/facundo/code/wye/jrr-refactor-trial/v2/STATE.md:250), [P11](/Users/facundo/code/wye/jrr-refactor-trial/v2/STATE.md:381)). **Smallest experiment:** compare the exact entry-plus-guides treatment against the exact combined treatment on the feature task and one held-out task family, including blind `overall` review and follow-up maintenance work. Include a human reviewer to test whether adherence produces a more maintainable result.

2. **If hooks stay, implement them in the existing Rust binary using `symposium-sdk`.** Typed JSON, proper serialization and native filesystem APIs remove several defects together and avoid requiring `sh` on Windows. Keep detection unchanged initially so that implementation and policy effects remain separable. The crate already has an SDK handler, but this is more code and requires reliable binary distribution; cold acquisition must still fit Symposium’s budget ([src/main.rs:1-10](/Users/facundo/code/wye/jrr-refactor-trial/just-right-rust/src/main.rs:1), [handler guide](https://github.com/symposium-dev/symposium/blob/ab3510351027baae624c09dc0c62fd4e81e1881a/md/crate-authors/writing-a-hook-handler.md), [hook budgets](https://github.com/symposium-dev/symposium/blob/ab3510351027baae624c09dc0c62fd4e81e1881a/md/design/hook-flow.md)). Preserve explicit exit-2 handling: the pinned SDK’s `StopOutput::context` and `run()` do not provide a portable blocking replacement, and handler errors exit 1 ([SDK 0.1.1:498-515, 594-636](/Users/facundo/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/symposium-sdk-0.1.1/src/hook.rs:498)). **Smallest experiment:** contract fixtures for escaped paths, null IDs, dirty/unborn repositories, repeated starts, concurrent Stops and hostile state files, followed by Windows and Unix delivery smoke tests, including cold installation.

3. **Replace lexical checks with a small fixed structural rule set.** Parse whole files and intersect matched syntax spans with added ranges. Ast-grep or tree-sitter can distinguish comments, literals, nested types, multiline calls and test scopes, improving precision and coverage. They still cannot infer specified defaults, input provenance or whether an identifier needs a newtype. P9’s agent-written queries added no discernible benefit; P10’s fixed rules caused all three runs to introduce a command enum that the audit runs missed. However, P10 was tuned against the baseline, truncated results and had no blind review; it did not compare executed regex searches against ast-grep ([STATE, P9/P10](/Users/facundo/code/wye/jrr-refactor-trial/v2/STATE.md:274)). **Smallest experiment:** label the counterexamples above plus samples from two untouched repositories, measure precision/recall and runtime, then compare old versus new detection with the same feedback text and blind review.

4. **Give new-code, feature and refactor tasks different scope instructions.** One entry skill with three short modes may be enough; split into task-level skills only if selection benefits from separate descriptions. Refactor mode should inspect the requested existing scope; feature mode should permit narrow enabling changes. Both single-entry and task-level variants loaded reliably, so activation alone does not justify three skills. The audit arm provides evidence for a defect-finding workflow, while P6 warns that copying every exception into context can weaken useful changes ([REPORT §§4.4, 11.7](/Users/facundo/code/wye/jrr-refactor-trial/v2/REPORT.md:304), [STATE, P6](/Users/facundo/code/wye/jrr-refactor-trial/v2/STATE.md:183)). **Smallest experiment:** change only the scope/workflow text, holding hook logic constant, on feature and broad-refactor requests.

5. **Use additional events selectively, with bounded feedback.** `UserPromptSubmit` can refresh a short reminder or deliver pending results without depending on Stop. A debounced `PostToolUse` check can provide feedback for Copilot and Kiro, although Antigravity does not expose its post-tool context. Avoid blocking every write or checking every intermediate edit: that adds calls and catches incomplete code. A first-write `PreToolUse` gate has little supporting evidence: file-tool-only matchers fired in 4/18 runs; adding Bash reached 18/18, but rejecting the write did not improve the measured outcome. Tool names and argument shapes also differ across agents ([STATE, P7/P8](/Users/facundo/code/wye/jrr-refactor-trial/v2/STATE.md:235), [matcher contract](https://github.com/symposium-dev/symposium/blob/ab3510351027baae624c09dc0c62fd4e81e1881a/md/reference/hook-events.md#matcher)). Claude additionally offers native non-error Stop feedback and `stop_hook_active`; using these requires a native-format override or a Symposium adapter change, since the current canonical adapter drops them ([Claude Stop documentation](https://code.claude.com/docs/en/hooks#stop), [adapter](https://github.com/symposium-dev/symposium/blob/ab3510351027baae624c09dc0c62fd4e81e1881a/src/hook_schema/claude.rs)). **Smallest experiment:** replay a multi-turn editing sequence containing file tools, Bash heredocs, scripts and `cargo fmt`; count missed writes, redundant feedback, continuations and latency before another full quality trial.

6. **Run Clippy asynchronously, reporting only results for the current snapshot.** This could recover the type-aware coverage removed from the measured treatment without blocking inside five seconds. Debounce jobs, use workspace-aware arguments, tag results with source fingerprints, and discard stale results. The cost is substantial lifecycle complexity, Cargo contention and the possibility that no later event arrives. Symposium permits background processes to survive successful hook exit, but kills the process tree on timeout; Antigravity needs prompt or Stop delivery rather than post-tool context ([hook lifecycle](https://github.com/symposium-dev/symposium/blob/ab3510351027baae624c09dc0c62fd4e81e1881a/md/design/hooks.md), [Antigravity support](https://github.com/symposium-dev/symposium/blob/ab3510351027baae624c09dc0c62fd4e81e1881a/md/reference/agents/antigravity.md)). The trial never isolated Clippy’s contribution from regex feedback. **Smallest experiment:** first measure cold/warm workspace completion and stale-result rejection, then compare otherwise identical treatments with and without asynchronous Clippy.

7. **Test checklist-bearing descriptions, but do not replace the entry skill on that assumption.** Putting compact rules directly in guide descriptions might influence behavior even when guides do not load. That mechanism was not measured: the description probes tested triggering, and failed activation does not prove that metadata had no effect. Costs include a larger discovery listing, competing instructions and truncation risks; simply rewriting trigger prose already performed poorly ([description probe matrix](/Users/facundo/code/wye/jrr-refactor-trial/v3/descriptions/probe.md:74), [guidance on description size](/Users/facundo/code/wye/jrr-refactor-trial/v3/descriptions/guidance.md:65)). **Smallest experiment:** compare unchanged descriptions against compact checklist descriptions with no entry skill or hooks, measuring code quality as well as activation and including negative, non-Rust requests.
